用户侧流程 — 操作者只在两个节点决策

AutoForge 把「需求 → 上线」的链条自动化。操作者（人）只在两个审核闸口做决策：需求审核（AI 分析后）与 代码审核（AI 实现后）。其余分析、实现、测试、合并全自动。

所有人工节点集中在 功能审计 页（Audit.tsx）；需求从多渠道进入；会议室 是并行的协作/产出空间，可绑定项目并把文档写进 .autoforge/ 工作区。

底层模块流程 — Rust 引擎内部

后端纯 Rust（async/tokio），零外部依赖（SQLite）。任务经进程内 mpsc 队列调度，job_executions 幂等键防重复执行。所有 git 操作走 GitProxy 拦截危险命令；事件只走 event::emit(app, AppEvent) 单一出口（顺手沉淀通知收件箱）。

三类后台任务：Analysis（需求分析）、Execution（worktree 代码实现）、Merge（含 dev-sync / 测试门 / 安全门 / squash 落地 / 自托管隔离推送）；外加 Testing / Revert / SecurityAudit。并发由 Semaphore 槽位 + pending_review 背压阈值控制。
