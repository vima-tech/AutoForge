# 审核规范（初级版本）

## 审核节点 1：分析报告审核

### 批准条件
- 需求描述清晰，目标明确
- 可行性评估合理（无明显遗漏的技术风险）
- 优先级建议与当前项目实际情况匹配
- 非重复需求（或重复但有理由单独处理）

### 拒绝条件
- 需求模糊，无法形成明确的实现方案
- 技术上不可行或风险过高
- 与已有功能完全重复且无增量价值
- 需求超出当前项目范围

### 管理员建议格式
附加建议应包含：
- 具体的实现约束（如"只修改前端，后端接口不变"）
- 特别注意事项（如"注意向后兼容性"）
- 参考资料（如相关代码文件路径）

## 审核节点 2：实现报告审核

### 批准条件
- 实现报告清晰，改动范围合理
- 测试全部通过
- 预览环境可正常访问，功能表现符合预期
- 无明显潜在风险

### 修改条件
- 功能基本正确，但细节需要调整
- 有明确的修改方向可以描述给 Claude Code

### 拒绝条件
- 实现方向根本性偏差，修改成本高于重新实现
- 引入了不可接受的技术风险

### 迭代次数警示
- ≥ 3 轮迭代时，优先考虑手动介入或重新描述需求
- 手动介入比无限迭代更高效
