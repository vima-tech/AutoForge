# 需求分析规范（初级版本）

## 分析目标

判断"这个需求值得做吗？怎么做？"

## 评估维度

### 真实性（authenticity_score: 0.0–1.0）
- 内部来源（scan/monitor）默认得分 1.0
- 外部输入需评估：是否是真实功能反馈，而非测试/垃圾数据
- 低于 0.5 的需求记录原因，供管理员参考

### 可行性（feasibility_score: 0.0–1.0）
- 评估在当前技术栈下的实现难度
- 需要跨越多个系统边界的需求得分应偏低
- 依赖外部 API 变更的需求得分应偏低

### 优先级建议（1-10，10 最高）
- Critical 严重级别 → 建议 8-10
- High → 建议 6-8
- Medium → 建议 4-6
- Low → 建议 1-3

## 分析报告格式

```
## 需求摘要
≤200 字，描述理解的需求本质

## 真实性评估
得分：X.X / 理由：…

## 可行性评估
得分：X.X / 预估影响模块：[模块列表] / 主要风险：…

## 优先级建议
P{N} / 理由：…

## 重复检测
未发现重复 | 疑似与 Issue #{id} 重复，原因：…

## 修改方案摘要（供 Claude Code 参考）
- 主要改动方向
- 关键约束条件
- 需要避免的副作用
```

## 规范盲区处理
遇到规范未覆盖的情况，在报告末尾添加"规范盲区：[描述]"，由管理员决策后补充本规范。
