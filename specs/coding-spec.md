# 编码规范（初级版本）

## 修改范围约束
- 只修改任务所需的最少文件
- 不引入与当前需求无关的重构
- 不修改 `.env` 文件
- 不删除数据库历史迁移文件

## 代码质量要求
- 新增代码必须通过项目配置的 lint 检查
- 新增数据库列必须生成对应迁移文件
- 不引入明显的性能问题（N+1 查询等）

## 安全边界
- 不将密钥、凭证硬编码在代码中
- 用户输入必须经过验证和过滤
- 数据库操作使用参数化查询，禁止字符串拼接

## 初步测试要求
- 必须验证核心功能路径（happy path）通过
- 修改的接口必须返回期望的响应码
- 运行项目配置的单元测试，确保无回归

## 实现报告格式

```
## 改动摘要
≤150 字描述做了什么

## 修改文件列表
- path/to/file.py: 说明

## 测试情况
- 新增测试：N 个
- 通过状态：✓ / ✗（附失败原因）

## 潜在风险
无 | [描述风险点]

## 规范盲区
[如有遇到规范未覆盖的情况，在此说明]
```
