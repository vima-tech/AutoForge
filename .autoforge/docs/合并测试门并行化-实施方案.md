# 合并测试门并行化 — 实施方案（可直接照改）

> 目标：把 `tasks/merge.rs::run()` 中最重的 **Phase 1 dev-sync + 测试门 + 安全门**
> 移出 `merge_lock`，只让真正必须互斥的 **land（落地 dev）** 串行，从而让同项目多个
> 待合并 CR 的测试并行（受 `build_pool` 节流）。
>
> 适用范围尤其是 AutoForge **自管理自身**（所有 CR 同属一个项目，当前全串行）。
>
> 配套文档：本文件是「可行性方案」的实施细化版，落地按 §9 分阶段推进，全程带
> `merge.parallel_premerge` 开关，可即时回退到现有单锁逻辑。

## 2. 锁的双职责（必须先认清，否则会改错）

| 职责 | 说明 | 本方案处理 |
|------|------|-----------|
| **A 工作树互斥**（硬约束） | 非自管理快路径在主仓库工作树 `checkout dev && merge --squash && commit`（merge.rs:34）必须独占；自管理路径 `push origin/dev`（merge.rs:188）并发会被 git non-ff 拒绝 | **保留**：land 仍持 merge_lock，但 land 廉价（本地 squash 或一次 push） |
| **B 线性化测试**（软约束） | 锁横跨 Phase1→test→land 使得「测的集成态 == 落的集成态」 | **放宽**：测试移出锁；land 前用 §5 决策树「再校验」补回安全性 |

> 一句话：land 必须串行且廉价（保留 A）；test 昂贵且只碰隔离 worktree（可并行）。代价集中在 B，由 §5 + §8 兜底。

## 3. 目标状态机

```
            review_2 批准 / 自动合并门 / retry_merge
                          │ enqueue Premerge
                          ▼
                    pending_merge ──────────────┐ (启动恢复: → Premerge)
                          │ premerge_run 开始     │
                          ▼                       │
                    merge_testing  ──────────────┤ (启动恢复: → Premerge, 从头重测)
        ┌─────────────────┼───────────────────┐ │
   测试/安全失败        通过                 Phase1冲突
        ▼                 ▼                     ▼
  merge_failed /     merge_ready          merge_conflict
  merge_conflict   (tested_dev_sha 落库)   (现有 AI/三方解冲突)
                          │ enqueue Merge(land)
                          ▼
                    [land_run 持 merge_lock]
                          │ revalidate (§5)
        ┌─────────────────┼─────────────────────┐
   dev已动且冲突       dev未动/独立            dev动且重叠且干净
        ▼                 ▼                     ▼
  merge_conflict       land_on_dev          (退回重 Premerge 补测)
                          ▼
                       merged ──→ security_audit job + Innate(spawn)
```

新增状态：
- **`merge_testing`**：premerge 进行中（Phase1+test+安全门）。UI 显示「合并测试中」。
- **`merge_ready`**：premerge 通过、`tested_dev_sha` 已落库、等待 land。UI 显示「待落地」。

`pending_merge` 语义不变（已批准、进入合并流水线），保留以最小化前端改动。

> 简化选项：若想少加一个状态，可省去 `merge_testing`，premerge 期间维持 `pending_merge` + 发 `TaskProgress` 事件。但 `merge_ready` **必须**新增——崩溃恢复要据此区分「需重测」与「只需 land」。

## 5. 再校验决策树（land_run 持锁内，本方案核心）

```rust
// land_run() 内，已持 merge_lock + cr_lock：
let dev_now = rev_parse(&git, &resolve_dev_ref(...)).await; // origin/dev 优先，回退本地
let tested = session.tested_dev_sha.as_deref();

match (tested, dev_now) {
    // ① dev 未动：落的就是测过的组合，零额外成本
    (Some(t), Some(n)) if t == n => land_on_dev(...).await,

    // dev 前进了（兄弟 CR 落地）
    (Some(t), Some(n)) => {
        let moved = git_diff_name_only(&git, t, &n).await;      // dev 新增改动文件集
        let cr_files = parse_changeset(&session.diff_content);  // 本 CR 改动文件集（快照已存）
        if moved.is_disjoint(&cr_files) {
            // ② 独立改动（软件工厂常态）：干净 re-merge
            re_sync_dev(...).await?;            // sync_dev_into_worktree(dev_now)，必为干净
            if cfg.independent_fast_gate {       // P2：仅跑 compile/tsc 快速门
                fast_gate(...).await?;           // 失败 → 退回重 Premerge
            }
            land_on_dev(...).await
        } else {
            // ③ 重叠改动：必须补测集成态
            match re_sync_dev(...).await {
                Conflict => set_merge_conflict(...),     // 复用现有 UI / AI 解冲突
                Clean    => requeue_premerge(...),        // 退回重 Premerge（在锁外重测后再 land）
            }
        }
    }

    // 兜底：无 tested_dev_sha（旧数据 / 跳过 premerge）→ 退回当前行为：锁内 Phase1+test+land
    _ => legacy_inline_merge(...).await,
}
```

要点：
- **整段再校验+land 都在 merge_lock 内**，dev 只可能被持同一锁的兄弟 land 推进 → 锁内不存在并发推 dev，无 TOCTOU。
- `git_diff_name_only(a, b)` = `git diff --name-only a..b`。
- `parse_changeset` 从 `session.diff_content`（merge.rs:673 已快照）解析 `+++/---` 文件名，或退一步用 `git diff --name-only <base>..<branch>`。
- ③ 的「退回重 Premerge」让昂贵重测回到锁外，避免锁内长测——但代价是该 CR 多排一轮队。可配置为「锁内直接重测」以图简单（P1 默认），P2 再优化为退回。

### 6.3 `tasks/merge.rs`（拆分）

```rust
/// 合并前阶段：无 merge_lock，仅持 cr_lock（防解冲突并发写同一 worktree），
/// 受 build_pool 节流。通过则置 merge_ready + 落 tested_dev_sha，并入队 land。
pub async fn premerge_run(db, tx, app, cr_id) -> Result<()> {
    if !parallel_premerge_enabled(db).await {            // 开关关 → 走旧 run()
        return run(db, tx, app, cr_id).await;            // 保留旧函数作为回退路径
    }
    let cr_lock = state::cr_lock(cr_id); let _g = cr_lock.lock().await;
    // worktree 存在性检查（同 merge.rs:629）
    // 置 merge_testing
    // 快照 CR diff（同 merge.rs:664）
    // Phase 1 sync_dev_into_worktree → Conflict 分支同现有（置 merge_conflict / 自动解冲突）
    // 记录 tested_dev_sha = rev-parse(resolve_dev_ref)
    // 测试门 run_and_gate → 失败：dev_merged?merge_conflict:merge_failed（同 merge.rs:769）
    // 安全门 pre_merge_gate → 失败 merge_failed（同 merge.rs:805）
    // 通过：UPDATE worktree_sessions SET tested_dev_sha=?, premerge_at=datetime('now')
    //       UPDATE change_requests/issues SET status='merge_ready'
    //       enqueue("merge", "land:{cr}:{uuid}", JobPayload::Merge{cr})
    Ok(())
}

/// 落地阶段：持 merge_lock + cr_lock。再校验（§5）→ land_on_dev → merged。
pub async fn land_run(db, tx, app, cr_id) -> Result<()> {
    if !parallel_premerge_enabled(db).await {
        return run(db, tx, app, cr_id).await;            // 回退
    }
    let merge_lock = state::merge_lock(project_id); let _m = merge_lock.lock().await;
    let cr_lock = state::cr_lock(cr_id); let _c = cr_lock.lock().await;
    // revalidate（§5 决策树）
    // land_on_dev（不变）→ 成功置 merged + worktree remove + preview terminate
    //   + enqueue security_audit + Innate spawn（均沿用现有 run() 尾段）
    Ok(())
}

/// 旧 run()：保留不删。开关关闭、或 revalidate 兜底分支复用它（锁内 Phase1+test+land）。
pub async fn run(...) { /* 现状逻辑原样保留 */ }
```

> 关键：把现有 `run()` 尾段（merged 置态、worktree remove、preview terminate、security_audit
> 入队、Innate spawn）抽成 `fn finalize_merged(...)`，premerge/land/旧 run 三处复用，避免重复。

### 6.4 入队点改为 Premerge

```rust
// change_requests.rs review_2 批准：
enqueue(db, job_tx, "premerge",
    &format!("premerge:{}:approve:{}", cr_id, Uuid::new_v4()),
    JobPayload::Premerge { change_request_id: cr_id.to_string() }).await;

// execution.rs 自动合并门（同时修掉固定键卡死）：
enqueue(db, tx, "premerge",
    &format!("premerge:{}:autogate:{}", cr_id, Uuid::new_v4()),
    JobPayload::Premerge { change_request_id: cr_id.to_string() }).await;

// change_requests.rs retry_merge：
enqueue(&state.db, &state.job_tx, "premerge",
    &format!("premerge:{}:retry:{}", cr_id, Uuid::new_v4()),
    JobPayload::Premerge { change_request_id: cr_id.clone() }).await;
```

> 全部用唯一键：premerge job 幂等（重测无副作用），唯一键彻底杜绝「completed 行去重不派发」的卡死。

### 6.5 `runner.rs::requeue_orphaned_merges`（扩展）

```rust
// 退役死 job 行（premerge + merge 两类 pending/waiting/running）
// 1) pending_merge / merge_testing → 重排 Premerge（从头重测，幂等安全）
// 2) merge_ready → 重排 Merge(land)（revalidate 处理 dev 漂移，幂等安全）
for (cr_id, st) in pending_or_testing { enqueue Premerge :restart:uuid }
for (cr_id) in merge_ready          { enqueue Merge     :landrestart:uuid }
```

## 7. build_pool 成为真正的测试并发闸

移出 merge_lock 后，同项目测试并发**首次**真正由 `build_pool`（state.rs:81）决定（此前被 merge_lock 串死）。

- 默认值复核：当前默认 2（state.rs:83）。建议按机器核数/内存设 `execution.build_slots`（已支持热调 `set_build_slots`，state.rs:90）。
- 醒目文档化：这是「防 rustc/tsc 同时打满 CPU」的**唯一**闸；设太大会压垮机器，设太小并行收益打折。
- 与 CPU 背压（`reaper::system_overloaded`，runner.rs:162）正交叠加，双保险。

## 8. 风险登记与缓解

| 风险 | 触发 | 缓解 | 阶段 |
|------|------|------|------|
| **独立 ≠ 语义兼容** | dev 改 `foo.rs` 重命名函数，CR 在 `bar.rs` 加调用；文件不相交但集成后编译挂 | 独立路径不裸落，至少跑快速门（`cargo check`/`tsc --noEmit`，远快于全测试）；失败退回重 Premerge | P2 |
| **未测组合落入 dev** | 乐观跳测放入坏集成 | 合并后去抖集成门（dev 多次推进后跑一次完整测试）+ 失败告警/可选自动 revert；dev 是集成分支非 main，容忍短暂破坏+快速回滚 | P3 |
| **再校验 TOCTOU** | 读 dev_now 后 land 前 dev 又被推 | 再校验+land 全在 merge_lock 内，dev 只被持同锁兄弟推 → 已串行化 | P1 |
| **premerge 久占 cr_lock** | 长测试期占 cr_lock 挡解冲突 | 符合预期（同 CR 本就串行）；跨 CR 无影响 | — |
| **回退** | 新模型出问题 | `merge.parallel_premerge` 默认关，灰度开；关闭即走旧 `run()` 单锁逻辑 | P1 |
| **旧数据无 tested_dev_sha** | 升级前已 pending_merge 的 CR | revalidate `_` 兜底分支走 legacy 锁内 Phase1+test+land | P1 |

## 9. 分阶段实施

**Phase 0（已完成）**：Innate 收尾 spawn 出锁、land_on_dev 去重复 fetch、review_2 唯一键。

**Phase 1（最小可行，先拿大头）**
- 迁移 0066 + 模型字段。
- JobPayload::Premerge + dispatch + 拆 premerge_run/land_run + finalize_merged 抽取。
- 4 个入队点改 Premerge（含修 execution.rs 固定键）。
- requeue_orphaned_merges 扩展三态。
- 前端 + intake 新状态登记。
- **revalidate 先只做保守版**：`dev_now != tested` ⇒ 锁内重跑 Phase1+test+land（= 现有安全性；dev 未动时直接落）。低频/错峰项目立即受益，零安全损失。
- 开关默认 **关**，验证通过后再灰度开。

**Phase 2（并行收益最大化）**
- §5 disjoint 判定 + 独立路径快速门 + ③ 退回重 Premerge。
- 让「批量、互相独立」的常态从「串行重测」变「并行只测一次 + 廉价落地」。

**Phase 3（安全网）**
- `tasks/integration_gate.rs`：合并后去抖完整集成测试 + 失败告警/可选自动 revert。

**Phase 4（调优）**
- build_slots 自适应；Settings 暴露并行度与各开关。

## 10. 测试计划

`tasks/merge.rs` 已有 5 条单测 + setup 脚手架（merge.rs:1011 起），扩展覆盖：

1. **dev 未动** → land 不重测（断言无第二次 run_and_gate；可用计数桩）。
2. **dev 动 + 独立文件** → 干净 re-sync + （P2）快速门 + land。
3. **dev 动 + 重叠 + re-sync 干净** → 退回重 Premerge / 锁内重测。
4. **dev 动 + 重叠 + re-sync 冲突** → merge_conflict。
5. **premerge 测试失败**（dev_merged 与否两分支）→ merge_conflict / merge_failed。
6. **安全门拦截** → merge_failed。
7. **崩溃恢复**：merge_ready 孤儿 → 重排 land 幂等无重复落地；merge_testing 孤儿 → 重排 premerge。
8. **并发集成测**：同项目 3 CR（2 独立 1 重叠）并发 premerge+land → dev 最终态正确、land 确为串行、重测仅发生在重叠 CR、build_pool 上限未破、最终 dev 可编译。
9. **回归**：`parallel_premerge=off` 行为与现状逐字节一致（land_on_dev 既有 5 测须仍全绿）。

## 12. 不做 / 暂缓

- **不做**「独立 CR 完全裸落不测」：`disjoint ≠ 语义兼容`是真实坑，至少跑快速门。
- **暂缓** build_slots 自适应到 Phase 4。
- **暂缓** 跨项目 land 并行（不同 project 的 merge_lock 本就独立，已天然并行，无需改）。
