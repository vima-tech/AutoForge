# 全量上下文基质 · 万物可引 · 实施契约

> 状态：实施契约（含落地计划与验收口径）
> 版本：v1.0 · 2026-07-01
> 定位：把《灵活方法论与上下文基质设计》**原则二**（"上下文随处可取"）从"精选几种来源"升级为
> **系统里任何信息默认可寻址、可引用、可回灌**。这是一条**贯穿全系统的设计理念**，等同于 `DESIGN.md`
> 对 UI 的约束力：后续所有开发（包括 AutoForge 派出去的编码 Agent）都必须遵守本契约。

---

## 0. 一句话

**AI 原生 = 系统里产生的任何一条信息，从诞生那刻起就默认是"可被寻址、可被引用、可回灌给任何 Agent"的上下文；
不可寻址是例外（仅密钥 / 基础设施），要寻址不是特权。**

---

## 1. 为什么要改（现状诊断）

- 基质 `source_kind` 词表声明了 **16 种**来源，但真正有"活体钩子"把数据灌进索引的只有 **5 种**
  （issue / incubator_draft / code_agent_log / cr_review / agent_output）。
- 用户明确想要的三类——`.autoforge` 文件、`llm_trace`、会议室原始消息——恰恰全是"声明了但没接线"的死词表。
- 全库 **~50 张表**，绝大多数连词表都没进。
- 根因：架构是 **push（每个子系统写数据时得记得主动 `register`）**。这是 allowlist 式手工接线，
  "16 声明 5 落地"的词表腐烂证明了：**靠人记着接线，永远会漏**。push 模型结构上保证不了完整。

---

## 2. 四条不变量（本契约的核心，违反即回归）

| # | 不变量 | 违反后果 |
|---|---|---|
| **I1 产生即可寻址** | 任何内容表的行、任何 `.autoforge` 文件，**无需接线**即可被枚举 / 引用 | 又退回词表腐烂 |
| **I2 单一寻址空间** | 一条信息一个稳定 `id`（`<source_kind>:<source_id>`）；`context_ref` 是全系统唯一引用原语 | 各功能点各造窄白名单 |
| **I3 默认全包、黑名单排除** | 默认纳入一切承载内容的表 + `.autoforge`；只显式排除密钥 / 基础设施 | 覆盖不全 或 密钥泄漏 |
| **I4 信任分级贯穿** | 外部来源（`external_untrusted`）回灌前必过 `has_obvious_injection` | 提示注入 |

## 3. 架构翻转：push-register → pull-provider

`context_index` 从"真源"降级为**可选缓存**；枚举改为**从数据活查**。加一种来源 = 加一条声明，一处。

### 3.1 provider 抽象（`core/context_providers.rs`）

```rust
#[async_trait]
pub trait SourceProvider: Send + Sync {
    fn kind(&self) -> &'static str;
    fn trust(&self) -> &'static str { trust::TRUSTED }
    async fn enumerate(&self, db, project_id, repo_path: Option<&str>, limit) -> Result<Vec<ContextItem>>;
    async fn fetch(&self, db, source_id, repo_path: Option<&str>, max_chars) -> Result<String>;
}
```

两类实现：
- **`DbTableProvider`**：由一条编译期静态 `TableSource` 声明驱动，一个 struct 通吃所有表来源。
  加表来源 = 往静态 `SOURCES` 数组加一行（I1）。
- **`WorkspaceFileProvider`**：walk `.autoforge/{docs,specs,deliverables}` + `claude.md` / `agents.md`
  （文件系统，非 DB），复用 `workspace.rs` 的越界守卫读取。

### 3.2 `TableSource` 声明式来源

```rust
pub struct TableSource {
    pub kind: &'static str,          // source_kind
    pub table: &'static str,         // 主表
    pub id_col: &'static str,        // 主键列（source_id）
    pub title_sql: &'static str,     // 生成标题的 SQL 表达式（静态字面量，非用户输入）
    pub content_col: &'static str,   // 懒取正文的列（显式点名 → 密钥列天然不被取）
    pub time_col: &'static str,      // 排序时间列
    pub stage: &'static str,         // origin_stage
    pub bulky: bool,                 // 大体量 → 懒取保尾摘要
    pub scope_from: &'static str,    // FROM+JOIN 片段（项目作用域）
    pub scope_project: &'static str, // 项目列限定，如 "c.project_id"；"" = 全局来源
    pub trust: &'static str,
}
```

**SQL 注入边界**：`table / id_col / title_sql / content_col / scope_from` 全部是**编译期 `&'static str` 字面量**，
由开发者维护，**永不承载用户 / 外部运行时输入**；运行时数据（`project_id` / `source_id`）一律走 bind 参数。
再加一层防御：注册表构建时校验所有标识符类字段匹配 `^[a-z_][a-z0-9_.]*$`，typo 也无法逃逸成注入。

### 3.3 装配与消费

- `core::context::list` → 遍历命中的 provider 活查 `enumerate`，合并（缓存命中优先）。
- `core::context::fetch_content` → 按 `source_kind` 派发到 provider `fetch`（替代原硬编码 scheme match），
  保留 `keep_tail` / `is_bulky` / `safe_truncate` 逻辑。
- `select`（纯函数排序裁剪）**完全不动**。`ContextRequest` / `assemble` 对外形状不变 → 上层零改。
- 现有 5 个 `register` 钩子**保留**作缓存预热，pull 模型下不再是必需（二期可删）。

## 4. 安全边界（I3 / I4）

### 4.1 密钥 / 基础设施硬黑名单

```rust
const NEVER_CONTEXT: &[&str] = &[
  // 密钥（即使已加密也不可浏览）
  "llm_configs", "widget_tokens", "intake_configs", "notify_channels",
  // 基础设施 / 自指 / 无内容
  "app_settings", "job_executions", "context_index", "conversation_reads", "_sqlx_migrations",
];
```

- 这些表**不出现在 `SOURCES` 里**；单测断言 `SOURCES` 的表与 `NEVER_CONTEXT` 零交集。
- 配置类来源（`agents` / `code_agents` / `mcp_servers`）**字段级脱敏**：只点名非密文列
  （name / role / model / transport / command…），**绝不**点名 `api_key` / `token` / `env_json` / `headers_json`。

### 4.2 信任分级

内部产生 = `trusted`；外部来源（`mcp_result` / `web_result`）= `external_untrusted`，`fetch` 回灌前过
`has_obvious_injection`（沿用既有闸，不因"全包"松动）。

## 6. 接通消费侧（"可寻址 → 被址"）

基质当前几乎无人消费（仅孵化台起草）。全量若不接消费侧即空转。

- **D1 会议室主编排**：`orchestration::assemble_conversation_context` 把用户在编辑器 `@` 显式引用的
  `context_ref` 作为 `refs` 交 `context::assemble`，正文**追加**注入 prompt（只注入显式引用的，过预算 + 注入闸）。
- **D2 编码工单**：`build_change_request_from_conversation` 的 `work_context` 同理带上显式引用。
- 都是**加法**：既有拼装不变，只在末尾追加"操作者引用的上下文"段，零回归。
