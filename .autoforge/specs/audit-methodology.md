# 代码扫描与审计方法论（浓缩版）

> 供 AutoForge 的安全审查 / 风险分级 / 测试角色与流水线复用。完整版见
> `.claude/skills/code-audit-scan`（Claude Code 外壳 skill）。本文件随项目上下文
> 自动注入，是 AI 审计/测试时的工作准则。

## 核心原则

- **有据可依**：每个发现给出 `file:line` 与具体机制（source→sink 路径），不臆测。
- **严重度 × 置信度分开**：高影响 ≠ 已确认。speculative 必须标注"需运行时验证"。
- **追数据流，不靠直觉**：从来源追到落点，漏洞 = 这条路径上缺失或错误的 guard。
- **逐类逐条**：按下方清单逐项枚举调用点并判定；无问题也要明确记"已查无问题"。
- **不信任任何越界数据**，包括 LLM/Agent 自己的输出，以及你自己刚做的修复。

## 数据流：source → sink

- **来源（不可信）**：IPC 命令参数、HTTP/webhook、CLI/env、文件、队列、由以上写入的
  DB 行、**LLM/Agent 输出**。
- **落点（危险）**：shell/进程、SQL、文件路径、git、外发 HTTP(SSRF)、反序列化、
  模板/格式化串、动态执行、渲染到 DOM、二次 prompt、离开后端的响应。
- **代理/单一入口**：凡"必须全走某处"的规则（git 代理、IPC 层、消毒器、唯一合并触发），
  专门 grep 直连调用找**旁路**——漏洞多藏于此。

## 审计清单（逐类走，逐站点判定）

1. 注入：命令/SQL/模板/prompt。参数化查询;命令用 arg 向量而非 `sh -c "<拼接>"`;
   prompt 注入过滤覆盖**所有外部+Agent文本**(含名义"可信"但实为外部撰写的来源)。
2. 认证与会话：常数时间比较;空/缺密钥=拒绝而非放行;令牌过期/轮换/吊销。
3. 越权（含对象级 IDOR）：每个特权操作有门禁;改 ID 不能越权访问他人对象;多租户隔离。
4. 路径处理：`..`/绝对/盘符穿越 + symlink 逃逸（canonicalize 后判包含;FS 操作前校验,
   `create_dir_all` 后若父目录可能是 symlink 需复检）。
5. 进程执行：arg 向量非 shell 串;限制传输协议(如 `GIT_ALLOW_PROTOCOL`、禁 `ext::`);
   子进程用进程组回收、`kill_on_drop`/超时,避免孤儿。
6. Web/界面面：XSS/CSRF/SSRF/开放重定向/SSTI/CORS/安全头;webview 的能力作用域与导航白名单。
7. 并发与状态：检查后行动(TOCTOU)改用**单条原子条件写**;锁跨 await;队列幂等;
   计数器在一条路径 +1 必须在**所有退出路径** -1(漂移→误触发阈值)。
8. 资源：读入内存/base64/解压前先限大小(防解压炸弹);句柄/临时文件/子进程泄漏;
   网络与子进程必带超时。
9. 密钥/加密/隐私：密钥不流向 UI/日志/错误/事件;不该明文落盘;不自造加密;
   PII 不过度采集或写日志;错误串不泄内部细节。
10. 错误与降级：禁"出错即放行/跳过"把安全检查变空操作;`let _ =` 吞掉安全相关写入失败;
    堆栈/内部细节不外泄。
11. 业务流程门禁：实现是否符合**既定顺序**(如先测后合、双人审核、先门禁后动作);
    步骤可否跳过/重排/重放;后续动作是真**阻断**还是只记日志;数值边界/整数溢出。
12. 反序列化/解析/配置：不可信 YAML/JSON/XML 进有副作用的类型;配置变成命令或网络目标。
13. 依赖与构建：版本锁;禁用框架/API;依赖 CVE;迁移**仅增不改**;配置无明文密钥。

## 定级（严重度 × 置信度）

- 严重度：🔴 Critical(可直接利用/凭证泄露/核心不变量被攻破) · 🟠 High(有前提的真实利用/
  越权/破坏受保护资源) · 🟡 Medium(需本地或认证/脆弱前提/纵深防御缺口) · 🔵 Low(加固/理论)。
- 置信度：Confirmed(端到端追通) · Likely(路径清晰但一环未验) · Speculative(模式匹配,需验)。
- 当前不可达但脆弱 → 最多 Medium,并注明原因(如"调用方均硬编码"),但不丢弃。

## 修复纪律

- 在**正确层级**修：补共享 guard,而非逐个调用点打补丁。
- **复审修复的交互**:把修改当作新变更重跑本方法论;枚举所改代码的**每条退出路径**
  (尤其 auto/bypass 支路),确认新 guard/计数/顺序不会与既有特性产生新泄漏/竞态/绕过。
- 加**先红后绿回归测试**(重排门禁、新增 guard 必须有);跑 build+test,零新警告;
  行为类改动须运行时验证(正向通过 + 负向被拦)后才算 done。

## AutoForge 专属不变量（须证伪）

- 合并唯一入口 = review_2 approved（或门控自动放行），且都经"合并前测试门禁"(worktree 上跑、失败阻断)。
- 所有 git 经 GitProxy;worktree 内 Agent 禁远程 git(`GIT_ALLOW_PROTOCOL=""`)。
- 工作区写入仅限 `.autoforge/docs|specs`,防 `..` 与 symlink 逃逸。
- 外部来源(含 GitHub/webhook/用户输入)必过 `has_obvious_injection` + LLM 安检;不可列为可信源。
- LLM api_key 永不回传前端;密钥不入日志/事件。
- 流水线计数在**所有终止路径**平衡(含 auto-merge 跳过 review_2 的支路)。
- 迁移仅增不改;新增 IPC 命令须在 `capabilities/main.json` 声明权限。
