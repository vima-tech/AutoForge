# AutoForge 宣传片原始素材（用户脚本）

## 产品一句话

AutoForge 是一个 "Human-Lite-in-the-Loop" 自主软件工厂（Tauri 桌面应用）：
AI 全自动完成 需求分析 → 代码实现 → 测试 → 合并，人类只在「需求审核」和「代码审核」两个节点做决策。

## 核心叙事角度（已锁定）：短板兜底 × 一人一条流水线

这套系统的优势不是让普通程序员「写得更快」，而是把他们最弱的三件事——
代码定位、工程纪律、安全边界——全部工程化兜底，同时把人的价值压缩到两个审核决策点上。
普通程序员的产出被放大到「一人管一条流水线」，而犯大错的空间被压缩到接近零。

## 六大优势（素材要点）

1. 角色升维：从「写代码的人」变成「做决策的人」。全链路自动化，人类只在两个审核节点介入。
   - 合并唯一入口：review_2 批准才触发 merge。

2. 产出放大：一个人同时推进多个需求。
   - 并发槽位 Semaphore（默认 5 个 CR 并行）+ 背压；
   - 异步任务队列 + 幂等键防重复执行；
   - 崩溃自愈：重启自动回滚卡死 CR、重建 worktree、重新入队；
   - 并行 premerge：同项目多 CR 合并前测试并行，落地串行持锁。

3. 补齐能力短板：
   - 代码情报预查（MCP code-intel）：执行前把符号预查到 file:line、调用者、影响面，注入 prompt，不用全仓 grep；
   - AI 需求分析：结构化 spec（blast_radius / affected_files / suspected_locations / 复杂度）+ 重复需求检测；
   - 分级选模型：risk_from_spec 判 Low/High——隔离小改动用快模型省钱，跨模块复杂改动用强模型保质；无 spec 保守按 High；
   - 规格渐进披露：list_specs / read_spec 工具按需拉取项目规范。

4. 工程纪律焊死在架构里（不遵守就走不通）：
   - 主仓 dev 只读 + git worktree 隔离执行，AI 永不直接在 dev 上改代码；
   - GitProxy 正则硬拦截危险命令（push main / force push / 改全局 config）；
   - 合并多重门：dev-sync + 测试门 + 安全门 → land 前再校验 dev 是否前进 → 必要时补测 → 落地后集成验证；
   - 提交信息自动规范：feat(module): 标题 [autoforge #短码]，squash 合并。

5. 安全兜底：
   - 所有外部输入（含 MCP 返回）过 has_obvious_injection，命中注入特征整条丢弃；
   - LLM/MCP 密钥 AES-256-GCM 信封加密落库，主密钥走系统钥匙环；
   - Agent 写文件强制限制在 .autoforge/ 工作区，路径越界直接拒绝；
   - 编码 Agent 子进程：传输层禁 remote git、进程组隔离、墙钟/空闲双超时真杀进程组。

6. 不被单一工具锁定：
   - CodeAgent trait 统一抽象 claude / codex / opencode 三家 CLI，项目级可覆盖；
   - 接新编码 Agent 有标准 6 步流程，技能投资不贬值。

## 目标观众

普通程序员 / 小团队技术负责人——不是 AI 极客。他们可能不信「AI 全自动」，
但会被「兜底」「审核点」「纪律焊死」「犯大错空间≈0」打动。

## 品牌调性

熔炉/余烬（Forge/Ember）：温暖深色 + 工业感 + 精密机械。
禁用词风：不要「赋能」「抓手」「闭环」等黑话；要直接、有金属感的工程师语言。
