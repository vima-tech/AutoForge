核心理念

AutoForge 不是 CI/CD 工具，不是代码审查工具，不是低代码平台。

它是一个项目无关的自进化软件工厂——接入任意仓库，以用户反馈和自动巡检为需求来源，人类只需看预览、拍板决策、随时叫停。

REVIEW 01

需求审核

需求分析 Agent 输出结构化报告：真实性评估、可行性分析、优先级与分类建议、重复检测、修改方案摘要。管理员可附加实现建议与约束条件，只有真正有价值的需求才进入实现环节。

REVIEW 02

实现审核 · 双栏预览对比

左栏：实现报告 + diff；右栏：生产版本 vs 本次改动版本实时预览——管理员亲手点击验证，而非盲看 diff。迭代 ≥ 3 轮：审核队列置顶高亮，系统建议"手动介入或重新描述需求"（软上限，不强制终止）。

CORE CAPABILITIES · 核心能力

01

实时预览系统

三层预览：Production（main 镜像）/ Dev（最新合并态）/ Worktree（审核中改动）。每个 worktree 独立容器 + 快照数据库，代码变更默认热重载，管理员可一键全量重启。

02

自进化运行

AutoForge 自身也是目标项目，用固定版本的成长框架迭代自己。框架版本切换协议保障升级安全。

03

背压式流控

三阶段渐进降速：正常(≤5并发) → 单线程降速 → 完全暂停(≥20积压)。资源始终保留，不强制销毁。

04

规范文档驱动

五大规范约束各 Agent：analysis-spec · coding-spec · testing-spec · preview-data-spec · review-spec。从初级版本出发，随运行经验通过"规范盲区 → 决策 → 沉淀"循环迭代。

05

项目无关接入

仓库根目录放置一个 autoforge.yaml，声明预览命令、测试框架、质量检查、分支策略、反馈入口。内置 Python / Node / Go / Ruby 等适配器，实现 Adapter 接口可接入任意技术栈。

06

双轨需求入口

外部输入轨（Widget / GitHub / API）与内部巡检轨（合并后响应 + 每日主动巡检）双线并行，统一流水线处理。

THREE AGENTS · 三大核心 Agent

需求分析 Agent

判断"这个需求值得做吗？怎么做？"——输出真实性评估、可行性/影响分析、优先级建议、重复检测、修改方案摘要。核心调试指标：识别无效需求准确率、评估与实际成本的一致性。

Claude Code Agent

准确实现经审核的需求，并初步验证正确性。重点：严格遵守编码规范与权限边界、修改范围最小化、实现报告清晰度（管理员能快速理解做了什么）。prompt 工程为关键，CLAUDE.md + 规范文档 + 分析报告 + 管理员建议全量注入上下文。

测试 Agent

双模式：被动响应（合并到 dev 后触发，验证改动 + 回归测试）+ 主动巡检（每日定时，全量测试套件 + 代码质量扫描 + 依赖安全检查）。发现问题自动按严重级别入队，生成质量周报。

SECURITY · Prompt Injection 三层防护

L1

输入消毒层

所有外部输入经独立 LLM 安全检测，识别并过滤恶意指令。最早拦截，恶意内容直接丢弃。

L2

行为审计层

每个 Git 操作由独立安全 Agent 实时审计。异常操作立即终止会话，操作日志完整保留。

L3

分支操作双重确认

任何涉及分支合并/删除的指令，必须经管理员手动确认。Claude Code 只能发起请求，无法独立完成分支操作——最终保障。
