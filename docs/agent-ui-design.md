# AutoForge Review Portal — Agent UI 交互设计文档

**版本：** v1.0  
**日期：** 2026-05-25  
**范围：** 人类在环（Human-Lite-in-the-Loop）审核界面的全部交互设计

---

## 1. 设计哲学

### 1.1 核心原则

**"让人类做对的决策，而不是花时间理解信息"**

AutoForge 中管理员的认知负担来自三个方向：

```
① 信息理解成本   — 读 diff、理解分析报告、判断风险
② 决策执行成本   — 点击、填写、确认操作
③ 上下文切换成本 — 在多个 Issue 之间来回切换记忆
```

UI 设计的目标是将三种成本同时最小化：

| 原则 | 具体表现 |
|------|---------|
| **信息分级** | 最重要的信息最大、最显眼；次要信息折叠/置灰 |
| **决策就近** | 看完报告立刻能点按钮，不需要滚动或切页面 |
| **状态持续可见** | 系统当前状态（并发槽位、背压阶段）始终在视野内 |
| **零迷失** | 任何时刻用户都知道"现在在做什么" |

### 1.2 管理员工作流模式

管理员的典型使用场景是**碎片化高频审核**——可能每隔 10-30 分钟收到一个通知，需要快速完成一次审核决策后继续其他工作。

因此 UI 必须支持：
- **快速上下文恢复**：打开页面立刻看到"要做什么"
- **一屏完成决策**：不需要多次滚动或切换 Tab
- **防误操作**：关键操作（批准合并）需要轻度确认

### 1.3 信息密度策略

```
低密度区（用于决策操作）        高密度区（用于深度阅读）
─────────────────────────       ──────────────────────────
按钮、状态标签、核心摘要         diff 内容、完整日志、审计记录
                                 可折叠，需要时展开
```

## 2. 信息架构

### 2.1 导航层级

```
AutoForge Review Portal
├── 需求队列          ← 首页，全局入口
│   ├── 待分析
│   ├── 待审核（Review 1）
│   ├── 执行中
│   └── 待审核（Review 2）
│
├── 审核节点 1        ← 分析报告审核
│   └── /{issue_id}
│
├── 审核节点 2        ← 实现报告 + 实时预览对比
│   └── /{cr_id}
│
├── 执行监控         ← Claude Code 实时日志
│   └── /{session_id}
│
├── 预览管理         ← 所有活跃预览环境
│
├── 审计日志         ← 全量决策记录
│
├── 质量周报         ← M8 实现后启用
│
└── 系统设置
    ├── 并发配置
    ├── 项目列表
    └── 通知配置
```

### 2.2 主要工作流路径

**路径 A（正常流程）：**
```
通知到达 → 需求队列 → 审核节点 1 → [批准] → 等待执行
                                              ↓
通知到达 → 审核节点 2 → [预览验证] → [批准合并]
```

**路径 B（修改迭代）：**
```
审核节点 2 → [修改] → 输入建议 → 等待 Claude Code 重新执行
                                         ↓
                              再次进入审核节点 2
```

```
  --green:  #4ade80  成功/批准/通过
```

### 3.2 决策按钮色彩语义

```
[批准]        → --green    最显眼，正向决策
[批准合并]    → --green    同上，加锁图标表示不可逆
[修改]        → --blue     中性，追加迭代
[拒绝]        → --red      危险操作，需轻度确认
[取消/返回]   → 透明底色    最低权重
```

```

  critical  bg: red-20%     text: red       border: red-30%
  high      bg: yellow-20%  text: yellow

  normal    不显示
  throttled bg: yellow-10%  border: yellow-30%
```

## 6. 审核节点 1（Review 1）

### 6.1 核心设计思路

Review 1 的目标是让管理员在 **≤ 2 分钟内** 完成对分析报告的审核决策。关键设计：

- **摘要优先**：分析摘要始终显示在首屏，完整报告折叠
- **置信度可视化**：分数用进度条+颜色表达，避免管理员解读数字
- **建议输入靠近按钮**：建议文本框和决策按钮在同一区域，减少视觉跳跃

## 14. 响应式与移动端策略

AutoForge 的主要使用场景是桌面管理后台，**不需要完整的移动端适配**。

移动端（< 768px）提供**最低可用性**：
- 只显示需求队列，支持快速审核 Review 1（批准/拒绝）
- Review 2 预览对比页在移动端降级为"仅显示报告，预览在新标签页打开"
- 执行监控、审计日志在移动端折叠为只读视图

桌面端（≥ 1024px）提供完整功能，最佳分辨率为 1440px 以上。

## 15. 组件规格汇总

### 15.1 已定义组件清单

| 组件名 | 用途 | 关键状态 |
|--------|------|---------|
| `StatusBadge` | 状态/严重级别标签 | pending / running / done / error |
| `SlotIndicator` | 并发槽位进度条 | N/M 格式，点击展开详情 |
| `BackpressureBanner` | 背压状态横幅 | 阶段 2 黄色 / 阶段 3 红色全屏 |
| `ScoreBar` | 真实性/可行性分数可视化 | 0.0-1.0 彩色进度条 |
| `IterationWarning` | 迭代次数警示 | ≥3 轮触发 |
| `PreviewFrame` | iframe 预览容器 | loading / ready / error |
| `PreviewPair` | 双栏预览对比 | 支持全屏切换 |
| `ReportCard` | 实现报告展示 | 折叠/展开 diff |
| `LogStream` | 实时日志流 | 实时/暂停切换 |
| `NotificationToast` | 通知提示 | action / warning / info 三种 |
| `DecisionBar` | 审核决策按钮组 | 固定底部 / 顶部 |
| `ConfirmDialog` | 不可逆操作确认 | 批准合并 / 拒绝 |
| `KeyboardHint` | 快捷键提示 | 底部悬浮条 |

### 15.2 设计 Token 引用方式

使用 CSS 自定义属性（Custom Properties），所有组件通过 `var(--token-name)` 引用，不硬编码颜色值。主题色可通过覆盖根级 CSS 变量快速切换。
